## 1. 文档定位与 Agent 阅读指南

### 1.1 本文档解决什么问题

Agent 没有跨会话记忆,每次新对话从零开始。记忆系统解决三个问题:**记什么、何时写、何时读**。本文档帮助选择记忆框架、设计记忆生命周期、评估记忆质量,并规避记忆投毒等安全风险。

### 1.2 Agent 阅读本文档的推荐路径

```text
目标:选记忆框架 → §4 框架对比 → §9.1 选型决策树
目标:设计记忆系统 → §2 分类学 → §5 生命周期 → §9 可执行框架
目标:评估记忆质量 → §6 评测基准
```

### 1.3 一句话核心结论

> **记忆是 Harness 的持久仓库,上下文是其临时工作台。** 记忆工程四问:记什么、何时写、何时读、如何纠错。

## 2. 记忆分类学

### 2.1 经典四分法(认知科学视角,综述 arXiv:2404.13501)

| 记忆类型 | 定义 | 实现机制 | 代表性实现 |
|---|---|---|---|
| **工作记忆** | 上下文窗口内信息 | 窗口截断 / 滚动摘要 | 对话 tokens、compaction |
| **情景记忆** | 具体交互事件(何时何地发生了什么) | 对话历史 / 时间线 | Generative Agents 的 memory stream |
| **程序性记忆** | 技能与策略(怎么做) | prompt 模板 / workflow / 工具缓存 | Skill、CLAUDE.md、hooks |
| **语义记忆** | 抽取出的通用事实 | 向量库 + 知识图谱 | Mem0、Zep/Graphiti |

### 2.2 新三维分类框架(2025-12)

arXiv:2512.13564(NUS/人大/复旦等)提出:**"形式—功能—动力学"三维分类**,认为长短时二分已不足:
- **形式**:令牌级 / 参数级 / 隐式
- **功能**:事实 / 经验 / 工作
- **动力学**:形成 / 演化 / 检索

并明确划清 Agent 记忆与 RAG、上下文工程的界限(见 §3)。

## 3. 记忆 vs 上下文:RAG 与上下文工程的分界

| 概念 | 本质 | 存储 | 访问时机 |
|---|---|---|---|
| **上下文(Context)** | 当前推理的临时工作台 | 有限窗口 | 每次推理全量可见 |
| **记忆(Memory)** | 跨会话的持久仓库 | 外部存储 | 按需检索进入上下文 |
| **RAG** | 从外部知识库检索事实 | 文档库(非个人经验) | 按查询检索 |
| **Skill** | 程序性记忆 | 文件夹 + 脚本 | 按任务加载 |

> 争议:Letta 等主张"记忆本质是上下文管理问题";新综述(2512.13564)则明确区分——记忆工程关注"何时写、如何纠错",上下文工程关注"何时读、如何编排"。

## 4. 主要框架深度对比

### 4.1 一览表

| 框架 | 哲学 | 记忆流程 | 适用场景 | GitHub star(约,2026-08) |
|---|---|---|---|---|
| **MemGPT / Letta** | 类 OS 虚拟内存 | 主上下文 + 外部存储,函数调用"换页";Memory Blocks、归档存储、动态摘要 | 有状态 Agent 平台、长期陪伴 | 约 24.1k |
| **Mem0** | 长期记忆即服务 | **提取→更新**双阶段流水线;向量 + 图双存储,按用户/会话/Agent 分层 | 即插即用记忆层 | 约 36.6k |
| **Zep / Graphiti** | 时序知识图谱 | 实体/关系随时间演化,增量图谱更新 | 关系复杂、多源动态场景 | 约 20.4k(Graphiti) |
| **Cognee** | 图谱 + RAG 管道化 | ECL(抽取-认知-加载)三步 | 结构化知识管理 | — |
| **MemOS** | 类 OS 分层 | 激活/参数/文本记忆三层 | 概念最完整的框架 | — |

### 4.2 定位差异(一句话)

```text
Mem0:最轻量通用,即插即用
Letta:重状态与自主管理(Agent 自己决定记什么)
Zep:重关系与时间线(实体随时间演化)
MemOS:偏概念框架(架构最完整,落地最少)
```

### 4.3 关键论文

| 论文 | 核心贡献 |
|---|---|
| [MemGPT](https://arxiv.org/abs/2310.08560)(Packer et al. 2023) | LLM 即操作系统:虚拟上下文管理,函数调用换入换出 |
| [Mem0](https://arxiv.org/abs/2504.19413)(ECAI 2025) | 提取→更新双阶段;向量 + 图双存储 |
| [Zep: Temporal Knowledge Graph](https://arxiv.org/abs/2501.13956) | 时序知识图谱:实体关系随时间演化 |

## 5. 记忆生命周期工程实践

### 5.1 记忆生命周期

```text
提取(Extract) → 存储(Store) → 检索(Retrieve) → 更新/冲突解决(Update) → 遗忘/清理(Forget)
```

### 5.2 各阶段要点与坑

| 阶段 | 要点 | 常见坑 |
|---|---|---|
| **提取** | **空闲/会话结束异步执行**(sleep-time agent),避免阻塞主循环;**显式写入优于全自动抽取** | 实时阻塞主流程;误提取噪声 |
| **存储** | 按用户/会话/Agent 分层;向量 + 图双存储(事实型用向量,关系型用图) | 单一存储无法覆盖两类信息 |
| **检索** | 相关度 + 时效性 + 重要性加权 | 检索到过期记忆 |
| **更新/冲突解决** | 新事实覆盖旧记忆需**时间戳 + 置信度校验**;Mem0 的 update 阶段专职去重/合并,避免记忆漂移 | 无冲突解决 → 记忆自相矛盾 |
| **遗忘/清理** | recency/importance 衰减、摘要压缩、归档分层 | 永久不清理 → 记忆膨胀、检索噪声 |

### 5.3 记忆提取提示词要点(供参考)

```markdown
在本次对话中,提取:
1. 用户的事实信息(偏好、背景、目标)——存语义记忆
2. 发生的事件(时间、上下文、结果)——存情景记忆
3. 与既有记忆冲突的信息——标记为待更新
忽略:临时性、一次性、无关内容
```

## 6. 评测基准

### 6.1 两大核心基准

| 基准 | 数据 | 测什么 | 备注 |
|---|---|---|---|
| **LoCoMo**(arXiv:2402.17753,ACL 2024) | 机器-人工混合生成,300 轮/平均 9K token,至 35 会话 | 问答、事件摘要、多模态 | 与 LongMemEval 并称"所有人都在刷的两大 bench" |
| **LongMemEval**(arXiv:2410.10813,ICLR 2025) | 500 题 | 五项能力:信息提取、跨会话推理、时序推理、知识更新、拒答 | 长会话下商业助手准确率掉约 30% |

### 6.2 局限性与厂商自测问题

- 两大基准已成"刷榜工具"
- **厂商自测(LLM-as-Judge)与第三方复测存在差距**:如 Mem0 论文自报 LoCoMo 上较 OpenAI 相对提升 26%、p95 延迟降 91%、token 省 90%+(均厂商自测);Zep 的 DMR 超越 MemGPT 亦为自报
- 对冲方案:Mem0 开源 **memory-benchmarks** 统一套件(LoCoMo/LongMemEval/BEAM,3000+ 题)
- 受控环境与真实运行时表现仍有鸿沟

> ⚠️ 选型铁律:看第三方独立复测,不信厂商自报分数。

## 7. 记忆安全与隐私

### 7.1 核心威胁

- **记忆投毒(Memory Poisoning)**:列 **OWASP Agentic AI Top 15 之首**——攻击者通过对话注入虚假记忆,长期污染 Agent 行为
- **MEXTRA 攻击**:黑盒条件下可抽取模型记忆
- **敏感信息泄露**:记忆库可能长期保存用户隐私

### 7.2 防护措施

1. **加密存储**:记忆库数据静态加密
2. **最小化存储**:只记必要信息,不记敏感原始数据
3. **可审计可删除**:支持查看、导出、删除全部记忆(GDPR 合规)
4. **输入校验**:对来自不可信来源的内容(如网页抓取)谨慎写入记忆
5. **权限分级**:团队记忆 vs 个人记忆(如腾讯云 Agent Memory 2.0 的 Team Memory)

## 8. 2025-2026 最新进展

| 进展 | 内容 | 意义 |
|---|---|---|
| **记忆编辑(Memory Editing)** | 两条路线:权重级编辑(ROME/MEMIT,单事实覆盖,但序列编辑有参数毒性累积问题)与外部记忆库编辑 | 精确修正单一事实而不影响整体 |
| **self-evolving 记忆** | 记忆自动化与 RL 集成成前沿;**ICLR 2026 首次系统揭示 self-evolving agent 的"错误进化(misevolution)"风险** | 自我进化的记忆需要纠错机制 |
| **记忆产品化** | 腾讯云 2026-08 发布 Agent Memory 2.0,新增 Team Memory(个人→团队记忆) | 记忆成为云服务标配 |
| **记忆 vs 上下文之争** | 新综述明确区分二者,提出记忆工程四问(记什么/何时写/何时读/如何纠错) | 学科边界逐渐清晰 |

## 9. 为 Agent 生成的可执行框架

### 9.1 记忆框架选型决策树

```text
需要什么记忆?
├─ 长期事实记忆(偏好/背景)→ Mem0(最轻量通用)
├─ 有状态、自主管理(Agent 自己决定)→ Letta
├─ 关系复杂、随时间演化 → Zep/Graphiti
├─ 结构化知识管理 → Cognee
└─ 研究/概念验证 → MemOS(参考架构)
```

### 9.2 记忆系统设计自查清单

```markdown
## 记忆系统自查
□ 记忆四问是否都有答案?(记什么/何时写/何时读/如何纠错)
□ 提取是否异步?(避免阻塞主循环)
□ 冲突解决是否有时间戳+置信度校验?
□ 是否有遗忘/清理机制?(防记忆膨胀)
□ 敏感信息是否加密 + 最小化存储?
□ 是否防记忆投毒?(不可信输入谨慎写入)
□ 是否支持审计与删除?(用户可查可删)
□ 评测是否用第三方复测?(不信任厂商自报)
```

### 9.3 供 Agent 生成记忆框架的元规则

1. **分层存储**:事实(向量)+ 关系(图)+ 事件(时间线)分开,各司其职
2. **异步提取**:空闲时执行,不阻塞主循环
3. **冲突必解决**:新记忆覆盖旧记忆必须校验时间戳与置信度
4. **记忆要会忘**:衰减、压缩、归档,防止检索噪声
5. **安全第一**:加密、最小化、可审计、防投毒
